# Inactive production operator-source installation

This installer adds a separate versioned copy of the reviewed native operator source. It reuses the existing native-10 vendor/Python runtime, proven task profile/config and approved validation recipe. It never writes services/timers, Hermes configuration, credentials, canonical repositories or database state. Installation creates no execution approval and makes no model call. Run the prepared host-specific wrapper only after its source and inactive installation are explicitly approved.

`install_operator.py` has fixed production allocations and a content-addressed candidate pin. The review wrapper first reruns the read-only host preflight and captures verified source bytes into a new root review. Its exact payload and wrapper checksums belong in the administrator review document, not an unpinned shell download. Source installation uses root-private journaling, exclusive intent/receipt records, directory fsync and per-allocation device/inode/owner/mode/content evidence. The worker root is UID996/0700 under a root-protected ancestor. Existing paths are refused even if contents match.

Actions: install (fresh only), inspect (read-only), resume (recorded partial installation), check (complete and unused installation), rollback (empty recorded installation only). Mutating actions require an absent/unambiguous task slot, no UID996 processes and an exactly disabled/inactive/dead legacy timer. Resume never adopts a path created without an inode receipt. Rollback checks every remaining allocation and contents before removing anything, refuses any runtime records or unexpected contents, and retains the installation journal. Interrupted rollback can continue; it cannot switch back to installation. No recursive deletion or parent ownership changes are performed.

An intent with no existing path can be resumed. An existing path without its allocation receipt, changed inode/content, malformed/temporary journal record, or headerless journal is ambiguous: retain it and inspect rather than deleting/adopting it. The wrapper must not overwrite a partial root review. A later recovery review may quarantine an incomplete source review only when it demonstrably never reached installation; original evidence remains retained. A missing final receipt is not permission to rerun a launch or push.

Installation rollback is deliberately limited to an unused release: approval/control, jobs and worker directories must all be empty. Once real task records exist, preserve them and prepare a separate migration/recovery procedure. Installer check is an installation acceptance check, not a production health endpoint. There is no activation timer to enable; execution remains an explicit root operator approval followed by one transient native task service. Further paid runs, merges and deployments retain their separate decisions.

Focused source tests cover installation/check/rollback, pre-existing paths, resumable interruption, receipt ambiguity, changed allocation/content, runtime-state preservation, interrupted rollback, source tampering, read-only inspection and fail-closed host checks. These tests mock privileges/service state; they are not an administrator installation or host acceptance result. The previously passed native-launch and publication acceptance fixtures remain evidence of those components; this installer still needs operator execution/acceptance.
