# Linear-first onboarding: implementation status

The approved v0.5 architecture introduces onboarding; it is not yet a live end-to-end capability. The four new work items are REV-55 through REV-58, mapped to SHRR-09 through SHRR-12 and the owned v0.5 project. Existing v0.4 work and production policy pins remain intact.

The initial source slice provides a draft-only coordinator and history adapter, an additive schema-6 project reservation, an operation-scoped history access policy, and a native planning-origin verifier. The coordinator never designates a draft or grants execution. Its origin verifier and storage are injected trusted components; untrusted agent JSON is not itself an origin proof. The history adapter's credential must be held by a dedicated broker that does not expose the raw history socket to the agent.

The reservation is immutable and unique by Linear organization/project and by owned project ID. Existing project-mapping submission checks a reservation inside its own transaction, so another mapping cannot claim the same identity under a different scope or project after a reservation commits. The schema-5-to-6 migration binds a fingerprint of prior data and schema to an explicit plan and preserves prior signed snapshots and evidence. A process can still fail between reservation, project creation, draft saving, and mapping; retries must reconcile exact IDs and bytes, and an unresolved conflict remains visible. Reservations are not approvals and cannot launch work.

The access v3 policy is additive: an explicitly configured planning-only peer has fixed agent, organization, teams and read scopes, no general history write grant, and can only reserve an identity, read permitted scoped data, create a reserved project, save its first draft, and record its exact project mapping. It cannot designate an architecture, write ordinary work, or change a scope. The planning origin verifier accepts only a verified human-directed native context and configured scope resolution; its result explicitly does not infer human agreement.

Disposable tests cover draft and mapping replay, lost responses, concurrent conflicting reservations, prior history and signed snapshots, schema-6 evidence access, scope and actor refusal, operation-level denial, and a real same-UID Unix socket. Synthetic Node tests exercise the verifier in the existing n8n container. These do not establish a cross-UID host deployment or a live Linear flow.

Still required: a protected cross-process verifier/broker with a trustworthy native Linear read and explicit scope resolver; planning-only Jarvis and Codex runtime entry points; draft work/issue creation and exact receipt reconciliation; operator decision/designation and safe execution admission; independent crash/concurrency and security acceptance; and operator-approved deployment and live pilots. No schema migration, service access policy, workflow, production agent permission, or production route has been changed by this source slice.
